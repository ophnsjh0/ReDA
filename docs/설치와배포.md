# ReDA 설치와 배포

ReDA를 개발용 Mac에서 돌리는 방법, VPS에 배포하는 방법, 시연용 인스턴스를 따로 띄우는 방법입니다. 앱 소개는 [README](../README.md), 시연해 보는 방법은 [시연 방법](시연방법.md)에 있습니다.

## 실행 (개발용 Mac)

```bash
uv sync
cp .env.example .env              # 내 주소, 분류기 키 등 설정
uv run reda gmail auth            # 브라우저로 Google 동의 (Gmail)
uv run reda calendar auth         # 캘린더 연결 (일정 등록을 쓸 때)
uv run reda poll --dry-run        # 메일함을 바꾸지 않고 새 메일과 규칙 필터 결과 보기
uv run reda poll                  # 분류하고 라벨 붙이기 (REDA_AUTO_DRAFT=true면 초안까지)
uv run reda summary --hours 24    # 출근 전 요약 미리 보기 (--send면 메신저로 보냄)
uv run pytest                     # 테스트
```

Google Cloud Console에서 만든 OAuth 클라이언트 파일(`credentials.json`)이 필요합니다. 설정 항목은 `.env.example`에 설명이 있습니다.

## 배포 (VPS)

서버에 Docker와 Hermes Agent 이미지가 있어야 합니다. 비밀 값(토큰, API 키)은 git에도 화면에도 남기지 않습니다. 아래의 `<…>`는 각자의 값으로 바꿉니다.

**1. 서비스 계정 만들기 (서버, 처음 한 번)**

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin reda
id reda                           # uid·gid를 compose.env에 적는다
```

**2. 소스와 설정 보내기 (Mac)**

```bash
ssh <관리계정@서버> 'mkdir -p ~/reda-staging/src'
git archive HEAD | ssh <관리계정@서버> 'tar -x -C ~/reda-staging/src'
ssh <관리계정@서버> "echo deploy-$(git rev-parse --short HEAD) > ~/reda-staging/src/deploy/VERSION"
```

서버의 `~/reda-staging/compose.env` (권한 600):

```bash
REDA_ROOT=/srv/reda               # 데이터 폴더
REDA_UID=<서비스 계정 uid>
REDA_GID=<서비스 계정 gid>
HERMES_IMAGE=<서버의 Hermes 이미지 ID>   # docker images로 확인, latest 대신 ID로 고정
REDA_AGENT_PROVIDER=openai-codex  # 초안 모델 제공자 (ChatGPT 구독)
REDA_AGENT_MODEL=<모델 이름>
```

**3. 비밀 파일 넘기기 (Mac)**

```bash
sh deploy/mac-handoff.sh <관리계정@서버>
```

Mac의 15분 자동 실행을 끄고(두 곳에서 같은 메일함을 처리하지 않게), 상태 DB 복사본, Gmail·캘린더 토큰, OAuth 클라이언트 파일, `.env`, 텔레그램 설정을 서버의 준비 폴더로 보냅니다.

**4. 설치 (서버)**

```bash
sudo sh ~/reda-staging/src/deploy/server-setup.sh ~/reda-staging
```

이미지를 만들고, 비밀 파일을 서비스 계정 소유(600)로 옮기고, 준비 폴더의 비밀 파일을 지운 뒤 컨테이너를 띄웁니다. 처음에는 ChatGPT 구독 로그인을 묻습니다. 제공자 목록에서 OpenAI Codex를 고르고, 나오는 주소를 브라우저로 열어 코드를 넣습니다. 다시 실행해도 됩니다(코드를 고친 뒤 2·4번).

**5. 확인 (서버)**

```bash
sudo docker ps --format '{{.Names}} {{.Status}}' | grep -E '^reda-(poll|schedule-bot) '   # 운영 둘 다 Up (name 필터는 시연 컨테이너도 잡는다)
sudo docker logs --tail 20 reda-poll              # 15분마다 "라벨 N통 ... 실패 0"
sudo docker exec reda-poll hermes -p reda auth status openai-codex   # openai-codex: logged in
sudo docker restart reda-poll                     # 켜지자마자 한 번 돌기 (시험할 때)
```

## 시연용 인스턴스 (운영과 따로)

리뷰어가 직접 메일을 보내 보게 하려면, 실제 고객 메일이 없는 시연용 Gmail 계정으로 인스턴스를 하나 더 띄웁니다. 같은 서버에서 `<REDA_NAME>-poll`, `<REDA_NAME>-schedule-bot` 컨테이너(예: `reda-demo-poll`)로 돌고, 데이터 폴더·Gmail 토큰·텔레그램 봇이 모두 운영과 따로입니다. 운영 컨테이너는 멈추거나 바꾸지 않습니다. 써 보는 방법은 [시연 방법](시연방법.md)에 있습니다.

준비할 것:
- 시연용 Gmail 계정
- 새 Google Cloud 프로젝트의 OAuth 클라이언트 (외부·테스트, 시연 계정을 테스트 사용자로, Gmail API·Calendar API 사용). 운영 프로젝트의 설정은 바꾸지 않습니다. 테스트 앱의 토큰은 7일마다 만료되니 시연 기간에만 씁니다.
- 시연용 텔레그램 봇 (BotFather). 운영 봇과 다른 새 봇이어야 합니다. 알림을 받을 사람이 먼저 봇에게 `/start`를 보냅니다.
- 시연용 서비스 계정 (권장): `sudo useradd --system --no-create-home --shell /usr/sbin/nologin <시연 서비스 계정>`

**Mac:**

```bash
cp deploy/demo.env.example .env.demo              # 값 채우기
mkdir -p ~/.reda-demo && cp <받은 OAuth 클라이언트 파일> ~/.reda-demo/credentials.json
REDA_ENV_FILE=.env.demo uv run reda gmail auth    # 브라우저에서 시연 계정으로 "허용"
REDA_ENV_FILE=.env.demo uv run reda calendar auth # 일정 등록을 보여 줄 때
# 시연 봇의 Hermes .env (두 줄): TELEGRAM_BOT_TOKEN=<시연 봇 토큰>, TELEGRAM_HOME_CHANNEL=<받는 사람 텔레그램 숫자 ID>
ssh <관리계정@서버> 'mkdir -p ~/reda-demo-staging/src'
git archive HEAD | ssh <관리계정@서버> 'tar -x -C ~/reda-demo-staging/src'
REDA_HANDOFF_ENV_FILE=.env.demo REDA_HANDOFF_STAGING=reda-demo-staging \
REDA_HERMES_PROFILE_ENV=<시연 봇 Hermes .env> sh deploy/mac-handoff.sh <관리계정@서버>
```

시연 모드의 `mac-handoff.sh`는 Mac 자동 실행을 끄지 않고, 상태 DB를 보내지 않습니다(서버의 시연 DB를 그대로 씁니다). 시연 설정이 운영 데이터 폴더·Gmail 토큰·봇을 가리키거나, 운영 토큰을 복사했거나, 봇 토큰이 운영과 같으면 멈춥니다.

**서버:** `~/reda-demo-staging/compose.env`는 운영 것을 복사해 네 줄을 바꿉니다. **`REDA_NAME`은 꼭 적습니다.** 빠지면 새 데이터 폴더에서는 설치가 멈춥니다.

```bash
REDA_NAME=reda-demo
REDA_ROOT=<시연 데이터 폴더>                       # 운영과 다른 경로
REDA_UID=<시연 서비스 계정 uid>
REDA_GID=<시연 서비스 계정 gid>
```

```bash
sudo sh ~/reda-demo-staging/src/deploy/server-setup.sh ~/reda-demo-staging
sudo docker logs --tail 20 reda-demo-poll
```

설치 스크립트는 데이터 폴더마다 주인 이름표(`.reda-name`)를 두고, 같은 이름의 컨테이너가 다른 데이터 폴더를 쓰고 있으면 멈춥니다. 그래서 시연 설정이 운영 폴더나 운영 컨테이너를 가리키면 손대기 전에 멈춥니다.

### 알림 받는 사람 바꾸기

알림(텔레그램 메시지)과 일정 버튼은 한 사람에게만 갑니다. 두 값을 **함께** 바꿔야 합니다. 하나만 바꾸면 알림과 버튼이 서로 다른 사람에게 가거나, 새 사람이 누른 버튼이 무시됩니다.

1. 받을 사람이 시연 봇에게 `/start`를 보냅니다.
2. 봇의 `getUpdates`로 그 사람의 숫자 ID를 확인합니다.
3. Mac에서 두 파일을 고칩니다.
   - `.env.demo`의 `REDA_SCHEDULE_CHAT_ID`
   - 시연 봇 Hermes .env의 `TELEGRAM_HOME_CHANNEL`
4. 위의 `mac-handoff.sh`(시연 모드)를 다시 실행합니다.
5. 서버에서 `server-setup.sh`를 다시 실행합니다. ChatGPT 로그인은 다시 묻지 않습니다.

### 끄기

시연 주소로는 누구나 메일을 보낼 수 있고, 보낼 때마다 분류·초안 사용량이 나갑니다. 시연이 끝나면 내립니다: `sudo docker stop reda-demo-poll reda-demo-schedule-bot`.

자세한 계획과 결정 사항은 `기획안/`에 있습니다.
