# ReDA 단계별 검증 기준

> `기획안/구현계획.md`의 각 단계는 이 문서의 **공통 게이트**와 **단계별 기준**을 모두 통과해야 끝난 것으로 본다.
> 검증 결과는 구현계획의 해당 단계 "진행 기록"에 남긴다 (통과/실패, 근거, 날짜).
> 검증 절차는 프로젝트 skill `reda-stage-gate`(`.claude/skills/reda-stage-gate/SKILL.md`)가 순서대로 실행한다.

---

## 작업 방식

- 단계마다 브랜치를 만든다: `stage-<번호>-<이름>` (예: `stage-2-rules`).
- 단계 작업을 마치면 공통 게이트와 단계별 기준을 확인한 뒤 `main`에 합친다.
- `/security-review`와 `/code-review`는 "현재 브랜치의 아직 합치지 않은 변경"을 검토한다. `main`에 바로 커밋하면 검토할 변경이 남지 않으므로 반드시 브랜치에서 작업한다.

## 판정 등급

| 등급 | 뜻 | 합치기 전에 |
|---|---|---|
| **높음** | 발송·데이터 유출·권한 탈취·인증 우회 가능, 또는 기획안의 설계 제약 위반 | 반드시 고친다 |
| **보통** | 잘못된 분류·초안이 생길 수 있는 버그, 오류 처리 누락 | 고치거나, 미루는 이유를 진행 기록에 적는다 |
| **낮음** | 가독성, 중복, 사소한 개선 | 선택 |

## 공통 게이트 (모든 단계)

| # | 항목 | 방법 | 통과 기준 |
|---|---|---|---|
| G1 | 테스트 | `uv run pytest` | 전부 통과. 새 기능마다 테스트가 있다 |
| G2 | 발송 차단 | `tests/test_no_send.py` | 통과. `send` 호출과 `gmail.send` 범위가 코드에 없다 |
| G3 | 공개 저장소 위생 | 브랜치 변경분에서 운영 정보(`기획안/운영메모.local.md`의 값)와 비밀(키, 토큰, 개인 키) 검색 | 0건. `.env`, `token.json`, `credentials.json`, `*.local.md`, `진행내역/`, `tests/private/`가 git에 없다 |
| G4 | 보안 검토 | `/security-review` | **높음** 0건 |
| G5 | 코드 검토 | `/code-review high` | **높음** 0건, **보통**은 처리 또는 사유 기록 |
| G6 | 설계 제약 | 아래 "설계 제약 점검표" | 해당 단계와 관련된 항목 전부 충족 |
| G7 | 기록 | 구현계획 진행 기록, `진행내역/진행내역.md` | 검증 결과와 남은 일이 적혀 있다 |

### 설계 제약 점검표 (CLAUDE.md "지켜야 할 설계 제약")

- [ ] 메일 발송 코드가 없다
- [ ] 에이전트(Hermes)가 쓸 수 있는 동작은 읽기·라벨·초안·일정 제안뿐이다 (terminal 등 임의 실행 도구는 꺼져 있다)
- [ ] 캘린더에는 사용자가 버튼을 누른 일정만 들어간다
- [ ] 근거가 없는 내용은 `[확인 필요]`로 남는다
- [ ] 애매한 메일은 `확인필요` 라벨만 붙고 초안은 없다
- [ ] 읽을 수 없는 첨부는 `첨부 확인 불가`로 표시된다
- [ ] 날짜가 불분명하면 일정을 제안하지 않고 묻는다
- [ ] LLM에 보내는 텍스트에 고객사 IP·계정 정보가 없다
- [ ] 사용자의 라벨 변경과, 라벨이 없던 메일에 대한 직접 답장이 기록된다

## 테스트 데이터 원칙

- 실제 메일은 공개 저장소에 올리지 않는다. 실제 메일로 만든 평가 세트(골든 세트)는 `tests/private/`에 두고 git에서 뺀다. 이 폴더가 없으면 해당 테스트는 건너뛴다(skip).
- 공개 테스트에는 지어낸 메일만 쓴다. IP는 문서용 대역(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`), 도메인은 `example.com` 계열을 쓴다.

## 단계별 기준

### 1단계 — 개발 기반
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| Gmail 연결 | 수동: `uv run reda gmail auth` | 내 주소가 출력되고 토큰 파일 권한이 600이다 |
| 새 메일 목록 | 수동: `uv run reda poll --dry-run` | Gmail 화면의 받은편지함과 목록이 일치한다 |
| History 동기화 | 자동 테스트 | 처음 동기화, 증분, 여러 페이지, 만료(404) 재동기화가 모두 통과한다 |
| 상태 DB | 자동 테스트 | 스키마 버전, 재열기, 중복 기록 방지, 파일 권한 600 |

### 2단계 — 분류·라벨
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 규칙 필터 | 자동 테스트 (지어낸 메일) | no-reply, 마케팅 발신자, 제목 키워드, 참조 전용이 `참고`가 된다. 이때 **LLM 호출 0회** (호출 횟수를 세는 가짜 분류기로 확인) |
| 그룹 중계 메일 | 자동 테스트 | From이 그룹 주소인 메일은 `X-Original-Sender`/`Reply-To`로 판정한다. 내 주소 없이 그룹 주소로만 받은 고객 문의가 `참고`로 빠지지 않는다 |
| `List-Unsubscribe` 오판 방지 | 자동 테스트 | 이 헤더만 있는 고객 문의가 대량 발송으로 분류되지 않는다 |
| 마스킹 | 자동 테스트 | IP·계정·비밀번호 표본 전부 가려진다. LLM으로 가는 요청 본문을 가로채 검사해 원래 값 0건 |
| 분류 정확도 | 골든 세트 (실제 메일 100통 이상, 사람이 정답을 단 것) | `답장필요` 놓침 5% 이하 (재현율 95% 이상), `확인필요` 비율 20% 이하 |
| 멱등성 | 자동 테스트 | 같은 동기화를 두 번 돌려도 라벨·기록이 중복되지 않는다 |
| 실패 격리 | 자동 테스트 | 메일 1통의 오류가 나머지 처리를 멈추지 않고 오류 수가 기록된다 |
| 동시 실행 | 자동 테스트 | 실행 중에 두 번째 실행이 시작되면 바로 끝난다 (잠금) |
| 실제 동작 | 수동: 1주일 | 직접 확인한 놓침 5% 이하 |

### 3단계 — 답장 초안
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 스레드 연결 | 자동 테스트 + 수동 | 초안이 원래 스레드 안에 붙는다 (threadId, In-Reply-To, References) |
| 형식 | 자동 테스트 | 초안 끝에 `---- [참고 — 보내기 전 삭제] ----` 블록과 근거 목록이 있다 |
| 근거 실재 | 자동 테스트 | 근거에 적힌 메일 링크·첨부 행이 실제로 존재한다 (지어낸 근거 0건) |
| `[확인 필요]` | 자동 테스트 (기획안 예시 ②) | 근거 없는 값(소프트웨어 버전)이 `[확인 필요]`로 남는다 |
| 언어 | 자동 테스트 | 원래 메일과 같은 언어로 쓴다 (한국어/영어) |
| 프롬프트 인젝션 | 자동 테스트 (공격 메일 20종 이상) | 라벨·초안 외의 도구 호출 0건, 다른 사람 주소로 가는 초안 0건 |
| 도구 제한 | 수동: Hermes 프로필 도구 목록 | terminal, code_execution, browser 등이 꺼져 있고 `reda-mcp`만 있다 |
| 초안 품질 | 수동: 초안 10통 | 7통 이상이 "3줄 이하만 고치면 보낼 수 있다" |

### 4단계 — 메신저 요약 + VPS 배포
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 컨테이너 권한 | 수동: VPS | 프로세스가 서비스 계정 uid로 돈다. root 프로세스 없음 (s6 초기화 제외) |
| 포트 | 수동: `docker port`, `ss -tlnp` | ReDA 컨테이너가 공개한 포트 0개 |
| 비밀 파일 | 수동 | 토큰·`.env` 권한 600, 서비스 계정 소유 |
| 시간대 | 수동 | 요약이 설정한 KST 시각 ±5분 안에 도착한다 |
| 15분 동기화 | 수동: 2일간 로그 | 빠진 실행 없음, 실패 시 운영자 알림 |
| 재시작 | 수동: gateway 프로세스 종료 | 자동으로 다시 뜨고 다음 실행이 정상 |
| 업데이트 | 수동: 배포 절차 1회 | 사용자 메모리·토큰·상태 DB가 유지된다 |

### 5단계 — 시범 운영 (2주) — 기획안 성공 기준
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 놓침 | `reda report` | 답장필요 놓침 5% 이하 |
| 초안 | `reda report` (보낸 메일과 초안 비교) | 10통 중 7통 이상이 3줄 이하 수정 |
| 일정 | 9단계 이후 측정 | 날짜·시간 오류 0건 |
| 시간 | 사용 기록 | 하루 메일 처리 시간 1시간 이상 감소 |

### 6단계 — 사용자 연결 흐름
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 정상 흐름 | 수동: 테스트 계정 | 링크 → "허용"만으로 연결, 다음 동기화부터 라벨이 붙는다 |
| state 토큰 | 자동 테스트 | 재사용, 변조, 만료, 다른 사용자 것 → 모두 거부 |
| PKCE | 자동 테스트 | code_verifier가 없거나 틀리면 토큰 교환 실패 |
| 일부 권한만 허용 | 자동 테스트 | 필요한 권한이 빠지면 저장하지 않고 다시 연결을 안내한다 |
| 연결 해제 | 수동 | `/연결해제` 후 Google 계정에서 앱 접근이 사라지고 토큰 파일이 지워진다 |
| 전송 | 수동 | HTTP 요청은 HTTPS로 넘어가고, 콜백 외 경로는 열려 있지 않다 |

### 7단계 — 첨부 분석
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 형식별 추출 | 자동 테스트 (PDF, xlsx, docx, pptx, txt/log) | 지어낸 표본에서 텍스트가 나온다 |
| 행 번호 | 자동 테스트 | 근거의 행 번호가 실제 내용과 일치한다 |
| 읽을 수 없는 첨부 | 자동 테스트 (암호 PDF, 깨진 파일, 상한 초과) | `첨부 확인 불가`와 이유가 표시되고 처리는 계속된다 |
| 마스킹 | 자동 테스트 | 첨부 내용의 IP·계정도 가려진다 |

### 8단계 — 기술 문서 검색
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 검색 정확도 | 평가 세트 (질문 20개 + 정답 항목) | 상위 3개 안에 정답 항목 80% 이상 |
| 근거 표기 | 자동 테스트 | 초안 근거에 문서 이름과 항목 제목이 있고 실제로 존재한다 |

### 9단계 — 일정 제안·등록
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 날짜 변환 | 자동 테스트 (한국어·영어 표현 50개 이상, 요일·월말·연말·시간대) | 오류 0건 |
| 불분명한 날짜 | 자동 테스트 | "다음 주쯤" 등은 제안 없이 질문으로 바뀐다 |
| 버튼 없이 등록 금지 | 자동 테스트 | 버튼 응답 없이 `create_event` 호출 시 거부된다 |
| 근거 문장 | 자동 테스트 | 모든 제안에 원래 문장이 붙는다 |

### 10단계 — 파일럿
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 정확도 | 사용자별 `reda report` (2주) | 전원 놓침 5% 이하 |
| 사용자 수고 | 인터뷰 | 서버나 설정 파일을 만진 사용자 0명 |
| 장애 알림 | 수동: 일부러 실패시키기 | 운영자 메신저로 알림이 온다 |

### 11단계 — 팀 단위 확대
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 사용자 격리 | 수동: 컨테이너 A에서 B의 파일 읽기 시도 | 실패 |
| 백업 복구 | 수동: 복구 훈련 1회 | 상태 DB·문서 색인 복구, 토큰은 백업에 평문으로 없음 |
